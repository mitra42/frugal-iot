# Frugal-IoT Loadcell

Frugal IoT - Loadcell scales application

A load cell (HX711) scale with a local menu, driven by buttons, to see the weight, tare it,
calibrate it, and choose a language. The menu has three parts that are chosen separately (see `src/control/menu.h`):

- **What it holds**: a tree of `Menu`, `MenuLine` and `MenuNumber`, built in `loadcell.ino`
- **How it is driven**: `Control_Menu_Simple`, with up, down, accept and back keys
- **Where it is shown**: the displays added with `addDisplay()`. This example always uses
  `Menu_Display_Serial`, so it runs on a board with nothing but buttons attached, and adds
  - an LCD with `ACTUATOR_LCD_WANT`
  - the LCD of another node with `CONTROL_MENU_LCD_NODE="esp32-12bc34"` (same org and project)
  - the OLED, on a board that has one
  - the captive portal page, with four buttons, with `CONTROL_MENU_CAPTIVE_WANT`

```
Scale
├── Weight      shows the reading; accept publishes it on menu/weight
├── Tare        sends 0 to loadcell/output
└── Settings
    ├── Calibrate   number, starting from the current reading, sent to loadcell/output
    └── Language    English / Deutsch / Bahasa Indonesia
```

## Wiring

Each button goes between its pin and GND. Holding up or down repeats, and gets faster the
longer you hold it. The pins are set per board in `platformio.ini` (the `build_flags_pins_*`
groups), so change them there.

| | S2 Mini | C3 72x40 OLED | D1 Mini |
|--------|---------|---------|---------|
| Up     | 3       | 3       | D5 (14) |
| Down   | 5       | 4       | D6 (12) |
| Accept | 7       | 10      | D7 (13) |
| Back   | 9       | 7       | none, so each menu ends in a "Back" row |
| HX711 DOUT / SCK | 33 / 35, or 16 / 18 with an LCD or OLED | 0 / 1 | D2 (4) / D1 (5) |
| LCD or OLED (I2C) | SDA 33, SCL 35 | built in | |

**One button** - define `SENSOR_BUTTON_ONE_PIN` instead of the four, e.g. the board's boot button.
Click for the next row (while editing a number, the next one down), double click to accept, hold
to step, faster the longer it is held. Each menu ends in a "Back" row to go back.

**No load cell** - leave out `SENSOR_LOADCELL_DOUTPIN` and `_SCKPIN`, to try the menu on a board
with nothing attached. The weight then shows nothing.

## PlatformIO

    pio run -e <env>              # build
    pio run -e <env> -t upload    # build and flash
    pio run -e <env> -t uploadfs  # write data/ (wifi credentials, config)

`<env>` is a name from the table below, for example `s2_mini`.

Before flashing, give the node your organization's enrolment secret: copy
`templates/platformio-secrets-local.ini.template` from the library to
`platformio-secrets-local.ini` beside `platformio.ini`, and paste the line the dashboard
gives you (gear icon > Nodes > Enrolment secret) over the placeholder. Without it the node
is refused until an administrator approves it by hand. `platformio-local.ini.template` is
the optional one, for your own debug flags and serial port. Neither file is committed.

## Arduino IDE

1. **Tools > Manage Libraries**, search for **Frugal-IoT** and install it. When it asks
   about the libraries it depends on, choose **Install All**.
2. **Tools > Board > Boards Manager**, and install the one for your chip: **esp32** by Espressif Systems, or **esp8266** by ESP8266 Community (add `https://arduino.esp8266.com/stable/package_esp8266com_index.json` under **File > Preferences > Additional boards manager URLs** first).
3. **File > Examples > Frugal-IoT > loadcell**, then **Tools > Board** and pick the row
   for your hardware.
4. **File > Save As** to keep your own copy, then give it your organization's enrolment
   secret: copy `platform-secrets-local.h.template` from the library's `templates/` folder
   (in your sketchbook, under `libraries/Frugal-IoT`) into the sketch folder (**Sketch > Show
   Sketch Folder**) as `platform-secrets-local.h`, and paste the secret from the dashboard
   (gear icon > Nodes > Enrolment secret). Without it the node is refused until an
   administrator approves it by hand.

Opening `loadcell.ino` from a download or a git clone does not install the library, and
the build stops with *Frugal-IoT.h: No such file or directory* - do step 1 first.

The LoRa board - Heltec WiFi LoRa 32(V3) - also needs LoRaMesher, which is not in the Library Manager:

1. Download [LoRaMesher as a zip](https://github.com/loramesher/LoRaMesher/archive/refs/heads/main.zip) - leave it zipped.
2. **Sketch > Include Library > Add .ZIP Library**, and choose that file.
3. **Tools > Manage Libraries**, and install **RadioLib**, which LoRaMesher uses.

Without it the build stops with *loramesher.hpp: No such file or directory*.

A board listed **twice** has two sets of settings in this example, and the Arduino IDE
has no way to ask for one - it only knows boards. So you get the row with an empty last
column unless you define that macro. It has to reach the whole build rather than just the
sketch, because the library's own sources read these settings too:

* **ESP32** - put the line `-DS2_MINI_LCD` in a file called `build_opt.h`,
  beside `loadcell.ino`. Despite the `.h`, that file holds **compiler flags, not
  C**: a `#define` in it stops the build with *no such file or directory*. The
  core copies it into the build and passes it to every source file.

Pick a board that is not in the table and the build stops with a message listing the ones
that are - rather than quietly compiling on the library's defaults, which for most boards
means the wrong pins.

Board not listed? `examples/all/platformio.ini` has `[env:]` sections for more boards,
including the LoRa ones. Copy one into this example's `platformio.ini`, add the pins this
example uses, and re-run `scripts/generate_platform_h.py` to rebuild `platform.h`.

## ESP8266: one extra step

In your saved copy, **Sketch > Show Sketch Folder** and rename
`X_loadcell.ino.globals.h` to `loadcell.ino.globals.h` - just remove the `X_`. If you
saved it under a new name, use that: `mytank.ino` needs `mytank.ino.globals.h`. Without it
the build stops with a message saying so. ESP32 and PlatformIO users leave the file alone.

The ESP8266 core reads only a file with exactly that name, which is how the settings in
`platform.h` reach it. The example cannot ship it under that name, because the Arduino IDE
then leaves the example out of **File > Examples**.

## If it does not fit

*"text section exceeds available space in board"* means this board's default flash
layout has less app space than the sketch needs. **Tools > Partition Scheme** and pick
**Minimal SPIFFS (1.9MB APP with OTA/128KB SPIFFS)** if your board offers it. Most of
these boards do not, and then:

1. **Sketch > Show Sketch Folder**, and rename `min_spiffs.csv` to `partitions.csv`.
2. **Tools > Partition Scheme >** choose **No OTA (2MB APP/2MB SPIFFS)**.

Over-the-air updates still work despite that menu label: step 1 is what sets the real
layout and it keeps both OTA slots. The menu choice only raises the size limit the IDE
checks against.
